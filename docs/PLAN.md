# Monaco.Presto — Implementation Plan

Port of the anime.js v4.5.0 animation model to .NET, with a framework-agnostic core and an Avalonia adapter. This document is the working plan: architecture, API shape, phase checklist and open decisions. Update the checklist as phases land.

Upstream reference: https://github.com/juliangarnier/anime (tag `v4.5.0`, `src/` and `tests/suites/`). Docs: https://animejs.com/documentation.

## 1. Goals and non-goals

**Goals**

- anime.js-level ergonomics from C#: one call to animate any property of any object or control, with staggering, keyframes, timelines and full playback control.
- Behavioral parity with anime.js for the timing model (delay, loop, loopDelay, alternate, reversed, seek, stretch, playbackRate, frameRate, composition) so upstream tests can be ported as the acceptance suite.
- A core with zero UI dependencies that can drive plain objects (view models, custom renderers, game-style loops) and is fully testable with a manual clock.
- An Avalonia bridge that makes controls first-class targets: `AvaloniaProperty` by name or typed reference, transform shorthands (`X`, `Y`, `Rotate`, `Scale`…), colors/brushes, thickness/corner radius/points, with correct thread affinity and lifetime handling.

**Non-goals (for now)**

- WAAPI-style compositor animation was a non-goal through Phase 8. It is now planned as Phases 9–12: the scope study, the verified Avalonia behavior and the design live in [docs/COMPOSITOR-PLAN.md](COMPOSITOR-PLAN.md).
- CSS-specific value handling (unit conversion between px/em/rem, CSS variables, DOM attribute animation). Only what maps to Avalonia survives: numbers, degrees/turns/radians for rotation, percentages where Avalonia uses `RelativePoint`/`RelativeRect`.
- Three.js-style adapters. The adapter interface is designed so that one could be written, but none ships.

## 3. Architecture

### 3.1 Core (`Monaco.Presto`)

```
Clock                      framerate + playback-rate bookkeeping (base of Engine, Timer)
└─ Engine                  root clock, one per ticking thread; owns the linked list of running Tickables; Update(now)
└─ Timer                   delay/duration/loop/alternate/reverse state machine, callbacks, controls
   ├─ Animation            Timer + linked list of Tweens over resolved targets
   └─ Timeline             Timer + linked list of child Timers/Animations, labels, positions
Tween                      one (target, property) interpolation: from/to channels, ease, composition
Renderer                   static Tick(tickable, time, muteCallbacks, internalRender, tickMode) and Render()
IFrameSource               Start(Action tick) / Stop(); core ships ManualFrameSource (tests) and StopwatchFrameSource (headless)
ITargetAdapter             CanHandle(object) → IPropertyAccessor Resolve(object target, string property)
IPropertyAccessor          GetValue/SetValue on a target + IValueCodec describing how to tween the value
IValueCodec                Decode(object) → channels (double[] or single double), Encode(channels) → object
```

Key ports, kept structurally identical to upstream for testability:

- **Linked lists** (`_head/_tail/_prev/_next`) for engine children and timeline children. Tweens hang off `Timer` itself (`_headTween`/`_tailTween`), mirroring upstream where `JSAnimation` reuses the renderable's list, so `Renderer` and the additive animation work on any timer. Zero-allocation ticking.
- **`tick()` in `render.js`** — the single function that turns absolute time into iteration time, handles loop/alternate/reverse/delay/loopDelay, fires callbacks and decides whether to render. This is the highest-value port; do it first and port `timings`, `controls`, `callbacks`, `directions` tests against it before any tweens exist.
- **Composition** (`replace` | `none` | `blend`): per (target, property) sibling tween registry (`ConditionalWeakTable<object, …>`), so a new animation on the same property cancels/blends the old one as in anime.js. `blend` uses additive animations (`additive.js`).
- **Function-based values** everywhere a number is accepted: `FunctionValue` is `(object target, int index, int total) => TweenValue`. Upstream's fourth argument is the timeline a value is resolved in, which only stagger positions use; here it lives on `Stagger` instead, which `Timeline.Add` invokes with `this` and `Animation` with `null`, leaving `FunctionValue` at three arguments. Its `prevTween` argument belongs to the Phase 7 WAAPI/draggable work.
- **Values**: `ValueKind.Number | Unit | Color | Complex`. Colors are parsed by the core (`PrestoColor` from `#rgb`, `#rrggbb(aa)`, `rgb()`, `rgba()`, `hsl()`, `hsla()`), so `colors.test.js` is portable. `Complex` covers typed structs that decompose into several numeric channels (Thickness, Point…) via the target's `IValueCodec`.
- **Time** is `double` milliseconds; `Engine.TimeUnit = Seconds` scales defaults and speed exactly as upstream.
- **Thread model** (Phase 9, [COMPOSITOR-PLAN.md](COMPOSITOR-PLAN.md) §4.1): one engine per thread that ticks it, no locks; the remaining shared statics (scratch values, ids, parser/accessor caches) are thread-safe — §4.1 has the inventory. `Presto.Engine` is the main (UI) engine and the ambient default; `Engine.Current` is a `[ThreadStatic]` that falls back to it, and `Engine.MakeCurrent()` installs another for a block — whoever owns a thread sets the engine, exactly as `Scope.Execute` installs defaults, so the factories keep the anime.js call shape instead of taking an `engine` parameter. Every `Timer` captures its engine at construction — its parent's, otherwise the ambient one — into `Timer.Engine` and resolves through it afterwards, so a UI-thread call on another engine's timer reaches that engine's clock — and trips *its* thread pin, which each engine arms in Debug on its first `Update()`.
  - Per engine: `Defaults`, `CurrentScope`, the children list, and the additive lookup table with its lookup animation (`Core.Additive`, driven from `Engine.Update()`).
  - Process-wide, so set before a second engine exists: `Globals.TimeScale` (written through `Engine.TimeUnit`, which only the main engine sets), `Globals.Precision` (exposed as `Engine.Precision`), `Globals.TickThreshold`, `Composer`'s replace lookups (keyed by target) and `Presto.Adapters`/`Presto.Codecs` — written once during initialization, read from every engine's thread, documented rather than locked.
  - `Then()` completes with `RunContinuationsAsynchronously`, so awaiting a non-UI engine's timer resumes off the tick, on the thread pool.

### 3.2 Avalonia bridge (`Monaco.Presto.AvaloniaBridge`)

- **`AvaloniaFrameSource`** — `TopLevel.RequestAnimationFrame(Action<TimeSpan>)`, re-requested each frame while the engine has children (exactly `requestAnimationFrame`). It is a one-shot on the global `MediaContext`, so any live `TopLevel` works; the bridge picks the first one from the application lifetime or from the first animated control, and falls back to a `DispatcherTimer` at `DispatcherPriority.Render` when no `TopLevel` exists yet. Installed automatically on first use (`PrestoAvalonia.EnsureInitialized()`), optionally explicit via `AppBuilder.UsePresto()`. While every window is minimized or the app or Browser page is in the background, the bridge sets `Engine.Hidden`, so with `PauseOnHidden` the engine pauses and stops requesting frames, which a minimized Win32 window would otherwise keep delivering (decision 91).
- **`AvaloniaObjectTargetAdapter`** — resolves properties on any `AvaloniaObject`:
  - typed: `AvaloniaProperty` instances (`Canvas.LeftProperty`, `Visual.OpacityProperty`);
  - by name: `"Opacity"`, `"Width"`, `"Canvas.Left"`, `"Margin"` through `AvaloniaPropertyRegistry` (owner type + attached);
  - transform shorthands `X`, `Y` (`TranslateX/Y`), `Rotate`, `Scale`, `ScaleX`, `ScaleY`, `SkewX`, `SkewY` — composed into a `TransformGroup` that the bridge owns on `Visual.RenderTransform` (mirrors `transforms.js`, which manages the CSS transform string). Values in DIPs / degrees; `"1turn"`, `"0.5rad"` accepted like upstream.
  - Value codecs: `double/float/int`, `Color`, `SolidColorBrush` (animates the brush's color, creating a local brush if the current one is frozen/shared), `Thickness`, `CornerRadius`, `Point`, `Size`, `Rect`, `Vector`, `RelativePoint`, and an `Easing` ↔ `Ease` adapter (`PrestoEasing : Avalonia.Animation.Easings.Easing`) so Presto eases can be used in Avalonia `Transitions` and vice versa. A decomposed `Matrix` codec is deferred until a property needs one — the transform shorthands go through the bridge's own `TransformGroup`.
  - Writes use `SetValue(..., BindingPriority.Animation)` so animated values sit above local values and are cleanly removed by `Revert()` (`ClearValue` at animation priority).
- **Control helpers**: `control.Animate(...)`, `Presto.Get(control, "X")`, `Presto.Set(control, …)`, `Presto.Remove(control)`, `ControlScope` that reverts everything created inside it when the control is unloaded.
- **Feature modules** (Phase 7): `Draggable`, `ScrollObserver`, shape helpers (`Geometry.ContourLength`, `TryGetPointAndTangentAtDistance` for drawable strokes and motion paths), text splitting and scrambling.
- **`Compositor` namespace** (Phase 10, [COMPOSITOR-PLAN.md](COMPOSITOR-PLAN.md) §4.2) — a Presto engine on the render thread, so a scene keeps animating while the UI thread is blocked. `CompositorCanvas` is the UI-thread `Control` that hosts a scene and marshals `Post`/`Invoke` to it; `CompositorScene` is what a user derives from, with an `Engine` and `Scope` of its own, `OnAttached`, `OnMessage`, `OnRender(ImmediateDrawingContext, Size)` and `PostToUI`. From attach on the scene belongs to the render thread, and `PostToUI` is the only way back to a control.
- Later: XAML attached properties/behaviors.

## 4. Public API sketch

The shape below is the target; details get refined while porting, but new APIs should stay in this style.

```csharp
using Monaco.Presto;
using Monaco.Presto.AvaloniaBridge;

// Timer (anime.js createTimer)
var timer = Presto.CreateTimer(new()
{
    Duration = 1000,
    Loop = true,
    FrameRate = 30,
    OnUpdate = t => label.Text = t.CurrentTime.ToString("0"),
});

// Animation on a control (anime.js animate)
var anim = square.Animate(new()
{
    ["X"] = 320,                                  // transform shorthand → RenderTransform
    ["Rotate"] = new TweenParams { From = -180 },  // per-property tween params
    [Visual.OpacityProperty] = 0.5,               // typed AvaloniaProperty
    ["Background"] = "#ff6b6b",                   // brush/color by name, string parsed by core
    Duration = 1250,
    Delay = Presto.Stagger(65, new() { From = StaggerFrom.Center }),
    Ease = Eases.InOutQuint,
    Loop = true,
    Alternate = true,
    OnComplete = a => { /* ... */ },
});

// Plain objects work with the same call (anime.js JS object targets)
Presto.Animate(viewModel, new() { ["Progress"] = 100, Duration = 500, Ease = Eases.Out(3) });

// Keyframes
Presto.Animate(box, new()
{
    ["X"] = TweenValue.Keyframes(new TweenParams { To = 100, Duration = 400 }, new TweenParams { To = 0, Ease = Eases.InQuad }),
});

// Timeline (anime.js createTimeline)
var tl = Presto.CreateTimeline(new() { Defaults = new() { Duration = 750, Ease = Eases.OutExpo } })
    .Add(a, new() { ["X"] = 200 })
    .Add(b, new() { ["Rotate"] = 90 }, "-=250")
    .Label("half")
    .Call(() => Console.WriteLine("half way"), "half")
    .Add(c, new() { ["Scale"] = 1.5 }, "<");

await tl.Then();              // anime.js .then()
tl.Seek(500); tl.Reverse(); tl.Stretch(3000);

// Animatable (anime.js createAnimatable)
var follower = cursor.CreateAnimatable(new() { ["X"] = 500, ["Y"] = 500, Ease = Eases.Out(3) });
follower.Set("X", pointer.X);   // eases toward the value over 500 ms

// Eases
Eases.OutQuad; Eases.Out(2); Eases.InOutBack(1.7); Eases.OutElastic(1, .3);
Eases.CubicBezier(.17, .67, .83, .67); Eases.Steps(5); Eases.Linear(0, "0.25 75%", 1);
Eases.Spring(mass: 1, stiffness: 100, damping: 10, velocity: 0); EaseParser.Parse("inOutQuint");

// Global defaults and engine (anime.js engine / defaults)
Presto.Defaults.Ease = Eases.Out(2);
Presto.Engine.Speed = 0.5;
Presto.Engine.Fps = 60;
Presto.Engine.Precision = 4;
```

Design notes behind the sketch:

- Parameter objects are `init`-only: `TimerParams`, `AnimationParams` and `TimelineParams` are records so `Timeline.Set` can override a few members with `with`; `TweenParams` is a plain class. `AnimationParams` exposes a `string` indexer (and, in the bridge, an `AvaloniaProperty` indexer via a derived params type) so property tweens and settings can mix in a single initializer. Indexer initializers are the only C# syntax that allows this mix, which is why a collection-initializer/`Add` design was rejected.
- `TweenValue` is a small struct with implicit conversions from `double`, `int`, `string` (`"+=50"`, `"#ff0000"`, `"1turn"`, `"50%"`), `TweenParams`, `FunctionValue` and typed values (`object`). It carries the raw value; adapters decode it against the property's current value, mirroring `values.js`.
- `LoopCount` has implicit conversions from `int` and `bool` (`Loop = true` ⇒ infinite).
- Every `Timer` is awaitable (`GetAwaiter`) as well as exposing `Then()` for parity; `Animation` narrows both to itself.
- `Timeline.Add(TimerParams, position)` and `Add(targets, AnimationParams, position)` are ambiguous when the first argument is a target-typed `new() { … }`, so a positioned timer child must name its type: `Add(new TimerParams { … }, 20)`.
- C# does not apply user-defined implicit conversions to lambda literals, so a delegate written inline needs its type named: `Ease = (Ease)(t => t)`, `["X"] = new FunctionValue((t, i, n) => i * 10)`. Values that already carry their own type (`Eases.*`, `Presto.Stagger(...)`) convert implicitly as the sketch shows.
- `utils.set()` is `Presto.Set(targets, parameters)`. It landed in Phase 3 rather than with the other target utils because it is the animation constructor's `fastSet` path; `Presto.Get`/`Presto.Remove` follow in Phase 4.
- `persist` exists only on anime.js 4.5.0's WAAPI path, so the core does not port it.

## 6. Testing strategy

- **Core**: xunit v3, no Avalonia. Tests drive `Engine.Update(now)` directly through `ManualFrameSource.Advance(ms)`, giving deterministic timing identical to how upstream tests use `engine.update()`/fake timers.
- **Upstream parity**: port suites from `tests/suites/*.test.js` one per phase; keep test names close to the Mocha `it()` descriptions so gaps are easy to audit. Suites that are DOM-only (`waapi`, `threejs`, `node`, `build`) are skipped.
- **Generated fixtures**: `tools/anime-fixtures/` (Node, `npm i animejs@4.5.0`) dumps JSON for easing curves (101 samples each), spring durations, stagger outputs and timeline positions; the C# tests assert within `1e-6`. Regenerate only when bumping the upstream reference version.
- **Bridge**: `tests/Monaco.Presto.AvaloniaBridge.Tests` on `Avalonia.Headless` with `[AvaloniaFact]`/`[AvaloniaTheory]` from `Avalonia.Headless.XUnit`. That package targets `xunit.v3.extensibility.core` 3.2.2, so `xunit.v3` is pinned to 3.2.x repo-wide (on 4.x, discovery throws `MissingMethodException`). It is also why `AssemblyInfo.cs` uses `CollectionBehavior(DisableTestParallelization = true)` rather than the 4.x `Parallelization` attribute. Tests run with a `ManualFrameSource` substituted for the RAF pump: codec round-trips, transform composition, animation-priority revert, scope lifetime. Headless tests run on virtual time: `CompositorTestBase` (bridge) and `TestFrames` (sample) advance Avalonia's compositor clock with the frame source (decision 79), so tests step frames and must not sleep (`Task.Delay`, `Thread.Sleep`) unless the code under test measures real time.
- **Visual**: the sample gallery is the manual acceptance surface; DevTools screenshots/property reads via MCP can be used to confirm end states.

## 7. Decisions and open questions

Decided (change here if reconsidered):

1. Time unit is milliseconds as `double`; seconds mode is an engine scale factor (parity).
2. `Defaults.Ease` is `Eases.Out(2)` like upstream, not linear.
3. Property tweens use the string indexer on params objects plus an optional fluent builder over it (`Presto.Build()`, Phase 14), which only builds params and so leaves the model unchanged; typed `AvaloniaProperty` indexer available in the bridge.
4. Transform shorthands write a bridge-owned `TransformGroup` to `RenderTransform`; if the user already set a non-Presto `RenderTransform`, it is wrapped as the first child rather than replaced.
5. Animated values are written at `BindingPriority.Animation` so `Revert()` restores user values precisely.
6. Bridge root namespace is `Monaco.Presto.AvaloniaBridge` to avoid shadowing `Avalonia.*`.
7. `ScrollContainer` pauses its 30 fps data timer with the wake window instead of leaving it running as upstream does, so the engine has no children and can stop the frame source while an idle observer is alive.
8. Scoping to a control lifetime is explicit: `PrestoAvalonia.CreateScope(control)` reverts when the root detaches from the visual tree (not on `Unloaded`, which never fires for a root detached before its `Loaded` job runs), and `Animate` never auto-scopes; no `AutoRevert` parameter in v1. (Phase 60's `WhenDetached` default `Pause` supersedes "`Animate` never auto-scopes" for detach, and `WhenDetached.Revert` is opt-in auto-scoping; decision 89.)
9. An `AvaloniaProperty` is animated through one `BindingPriority.Animation` binding per target that every frame pushes a value into, rather than the value entry per frame a `SetValue` at that priority creates (`Opacity`: 288 → 104 bytes/frame). A `double` property is bound through a typed `IObservable<double>`, so its number is pushed without boxing (`Opacity`: 104 → 80 bytes/frame); every other type keeps the untyped binding and boxes its value. These residual per-frame allocations are accepted for 0.1.0, all of them measured in the two `AllocationTests` suites: 80 bytes for the property-changed args Avalonia raises on each write, which is left to Avalonia and is now the whole cost of a `double` property and of a transform shorthand (which writes a reused `TranslateTransform`/`RotateTransform`), and 24 bytes per child a timeline re-renders internally at a loop boundary, where the core composes `Tween._value` as upstream does.
10. Both packages target `net10.0` only for 0.1.0. The sole blocking API is `System.Collections.Generic.OrderedDictionary<TKey, TValue>` (.NET 9+), which `AnimationParams`, `AnimatableParams`, `Keyframe` and `KeyframeExpander` use as an insertion-ordered map *and* as the `IReadOnlyList<KeyValuePair<string, TweenValue>>` the `Animation` constructor consumes; a trial `net8.0` compile with a stand-in for it produced no other error, and the bridge builds clean on `net8.0` against Avalonia 12.1.2. Multi-targeting therefore means carrying a hand-written replacement on a framework neither test project runs, which is not worth it before the API pass.

11. On Android the frame pump resolves its `TopLevel` from the first visual the bridge animates rather than from the application lifetime, because no lifetime there can answer. `IActivityApplicationLifetime` publishes only a `MainViewFactory`, which `AvaloniaMainActivity` invokes and assigns to the activity's content, leaving `ISingleViewApplicationLifetime.MainView` null; `ISingleTopLevelApplicationLifetime`, which the Browser and iOS lifetimes do implement, is `[PrivateApi]` and its `TopLevel` getter is inaccessible to consumers. Until a visual is animated, the 60 Hz render-priority `DispatcherTimer` pumps, so animations run either way. For the same reason the handover is tested through a seeded visual instead of a fake lifetime: Avalonia's lifetime interfaces are `[NotClientImplementable]` and cannot be implemented in a test.

12. Render-thread work is an explicit, separate API named after Avalonia's own term: `CompositorCanvas`, `CompositorScene`, `CompositorAnimation`, `AnimateOnCompositor`. `RenderThread*` was the alternative and `Composition*` was out, because the core already uses `Composition` for replace/none/blend. A scene owns its `Engine`: the UI thread never ticks a scene and the render thread never writes an `AvaloniaProperty`. The engine is ambient (`Engine.Current`) rather than a parameter on every factory, so the anime.js call shape survives.
13. Compositor animations on controls are a reduced, separate type, as upstream's `waapi` is, sharing no registry with UI-thread animations; a property with no composition counterpart throws instead of falling back to the UI thread, which would defeat the point. They compile by sampling a mirror Presto `Animation` (upstream's `linear()` approach), with a single-segment tween compiled exactly through `PrestoEasing` instead; `RotationAngle` is radians on the wire and Presto keeps degrees at the API. `CompositionSolidColorVisual.Color` would add background color to that set but only as a child visual drawn above the control's content, so backgrounds stay UI-thread work.
14. `Opacity` is owned through an `Animation`-priority binding for the life of a compositor animation, because the server animation dies the moment `Visual.Opacity` changes. Playback control is emulated by recompiling from the mirror's position; the mirror moves now and the server animation it compiles starts at the next commit, so the two run at most a frame apart until the next call, which samples the mirror again and puts them back in step. Measured compensation through `CompositionBatch.Processed` is not worth it until the skew is visible somewhere.
15. Layout transitions are FLIP, inverted onto the composition `Translation`, not an implicit animation on `Offset`. The `Offset` design was built first and measured: it does not animate on the Windows desktop backend, and a bare Avalonia implicit animation snaps identically, so it is not Presto misusing the API (COMPOSITOR-PLAN §4.4 has the evidence). Measuring First/Last on the UI thread and inverting onto `Translation` — never written by Avalonia, §2.2 — uses the explicit `StartAnimation` path that demonstrably survives a blocked UI thread, and additionally buys size changes and moves between parents. Enter/leave states (`enterFrom` / `leaveTo` / `swapAt`) stay out: they need a presenter hook, not a layout hook.
16. Browser runs compositor scenes and animations but does not survive a blocked UI thread, since its render loop is on the same thread; documented, nothing built for it. The Avalonia internals the whole compositor story rests on (the client setter's equality guard, `SetAnimatedValue(out)` removing the running animation, `Offset + Translation` composition) are pinned by `CompositorAnimationTests.InvalidateVisualDoesNotStopACompositorFade`, which has to be re-run when `AvaloniaVersion` moves.
17. The XAML surface is one attached property, `presto:Animate.OnAttached` (Phase 15), typed `AnimationBuilder?` so `x:Static`, a markup extension or a binding can supply it; it plays on visual-tree attach and reverts on detach. It is an attachment trigger only: since Phase 26 it is the "while attached" trigger for loops and timers tied to being on screen, such as a shimmer or a countdown, while entrances and exits (`Initial`, `Enter`, their fallback `Arrive`, and `Exit`) live on `Presence` (decision 23), state triggers on `Motion` (decisions 24–28), and the one-shot `OnTapped` and `OnChanged`/`Watch` beside `OnAttached` on `Animate` (Phase 23), so no separate behaviors layer is planned.
18. Connected animations from XAML (Phase 17) are three separate attached properties on the bridge's static `Connected` class (`Key`, `Motion`, `Anchor`), so each keeps its own bindings and style setters. The arriving element's `Motion` wins, with no fallback to the leaving side's; otherwise `Connected.DefaultMotion`. See [CONNECTED-ANIMATIONS-PLAN.md §6](CONNECTED-ANIMATIONS-PLAN.md#6-xaml-keys-phase-17).
19. `Stretch` deviates from upstream for top-level timers: it leaves `_offset` alone and rebuilds the tweens' absolute times from their scaled local times, instead of multiplying both by the stretch factor. A top-level offset is the engine time the timer was created at, and stretching from a setter's `1e-11` duration (an `Animatable` property with duration 0, which `Draggable` uses on every axis) multiplied it by ~10¹⁴, past the precision a frame needs: the release tween then started up to seconds late or never, depending on how long the engine had run. Upstream has the same arithmetic; timeline children keep it unchanged. Pinned by `AnimatablesTests.RetargetingAZeroDurationPropertyLongAfterTheEngineStartedStillEases`.
20. Spring momentum on `Animatable` (Phase 18) is opt-in (`PreserveVelocity`), because upstream's springs always start at rest and `Draggable` sets its release springs' velocity itself. The velocity is measured from the running tween's ease (a spring's `PureEase`, so sampling never raises its `OnComplete`) and handed to a fresh `Spring` with the same mass, stiffness and damping. The springs then set the animation's duration, overriding a duration the property declares. Only the scalar `Set` carries velocity; the channel form keeps today's behavior.
21. Values whose shape differs between their two ends go through `IReconcilingValueCodec` (Phase 19): the codec claims non-relative strings before the core parses them and makes both ends agree before `Homogenize`/`PadShorterValue`. Discrete fields (gradient kind, spread, units, inset) ride as channels and are read from the tween's `_toNumbers`. Gradient stops are resampled onto the union of both ends' offsets; a kind mismatch snaps the geometry to the end value's; a gradient eased to a color ends on a `SolidColorBrush`. `Brush.Transform` is not carried.
22. Exit animations (Phase 20) play on a ghost, not on the control: a bitmap snapshot (one per piece for split text, decision 80) in the window's `OverlayLayer`, placed at the element's layout slot and clipped by its former ancestors' `ClipToBounds` boxes. An element is ghosted only when it leaves on its own: its `AttachmentPoint` is still attached, and every visual up to the removed root wraps only it. Avalonia strips a removed branch's styles before any detach event, so the snapshot lends the branch's logical root to the nearest logically attached ancestor for the render, with `DataContext` pinned. A transform held by the shorthands is suspended for the render (the composer's group is emptied, which does not trip its re-assert) and moved onto the ghost as a `MatrixTransform`; any other render transform is baked into the snapshot, cropped to the element's box.
23. Lifecycle animations (Phase 21) are three `Presence` properties, `Initial`, `Enter` and `Exit`, driven by one tracker per element and one classification. An arrival walks up past the not-yet-loaded wrappers around the element (non-panel ancestors with one child) and stops at the first panel or other host: a loaded host (`Control.IsLoaded`) is an enter, anything else an initial load. A panel always stops the walk because it has one child for a moment while realizing its first item. A departure exits only through single-child wrappers out of a loaded parent, because a view shown again re-creates its item containers before it has loaded. Classification happens at attach, never at `Loaded`, which Avalonia raises after the first render. Arrivals under one panel in one pass share a batch, whose ordinals are the index function values and staggers see; `Stagger` rebuilds its cache when the target count changes (a deviation from upstream), so a shared stagger follows a growing batch. Inside a list, the list decides: the content of an item container enters only when its item was just added and exits only when it was just removed or the list reset, because a virtualizing panel detaches and re-attaches row content as it recycles containers on scroll, which plays nothing. Phase 26 adds a fourth property, `Arrive`, the fallback for both arrival moments: Initial plays `Initial ?? Arrive` and Enter plays `Enter ?? Arrive`.
24. State motion conditions (Phase 23) are ANDed tokens on the element itself, not a selector engine: `:pseudo-class`, `.class`, and a leading bare name matched against the tokens of `Motion.State` (its `ToString()` split on whitespace and commas). Descendant, child and template parts throw `ArgumentException`. See [MOTION-KIT-PLAN.md §2](MOTION-KIT-PLAN.md#2-phase-23--state-triggers).
25. Selector reach goes through style setters on `Motion.State`: a style such as `Border.card:pointerover Path.arrow` sets a token on the child, a child state names it, and when the selector stops matching the setter's value goes and the state leaves. Presto parses no selectors.
26. A state's rest is the property's base value, reverted to once the return completes. For an `AvaloniaProperty` it is `GetBaseValue` (everything below `Animation` priority), read as the property returns so a binding, style or local value changed mid-state is honored, or the property's default when nothing is set; for a transform shorthand it is the identity. When the return finishes while its animation still drives the property, the tracker reverts the `Animation`-priority value, uncovering an equal value, so nothing snaps.
27. Arrival snaps and detach reverts: on attach the states that hold are applied with `Presto.Set`, so a recycled container or a view shown again arrives in its state instead of replaying it, and detach cancels and reverts every state animation while the definitions stay. An opt-in to animate initial states was not built.
28. State animations compose by replace. Each transition plays one animation per entering state and one per leaving state, covering only the properties whose winner changed, and takes them over from where they stand: a hover during a `Presence.Enter` goes straight to the lift while the entrance keeps its other properties.
29. Effects (Phase 24) are bridge-owned shorthands, as transforms are (decision 4): per visual, an `EffectComposer` owns `Visual.Effect` (one `BlurEffect` or `DropShadowEffect`), a `ClipComposer` owns `Visual.Clip` (one `RectangleGeometry` or `EllipseGeometry`) and a `MaskComposer` owns `Visual.OpacityMask` (one `LinearGradientBrush`). Each writes its object at `Animation` priority and mutates it per frame, so `Revert` uncovers the user's own value. A visual holds one effect and one clip: a blur and a shadow, or an inset and a circle, animating it at once throw `InvalidOperationException` from the `Animate`/`Set` call, and one after the other switches the kind. An effect or reveal at rest (a blur of 0, a shadow faded to 0, a reveal ended fully visible) is removed rather than left costing an offscreen pass. See [MOTION-KIT-PLAN.md §3](MOTION-KIT-PLAN.md#3-phase-24--effects).
30. 3D rotation (`RotateX`, `RotateY`, `Perspective`) drives one `Rotate3DTransform` that `RenderTransformComposer` inserts into its group only once one of the three is animated, so 2D-only visuals keep their group. It sits between the scale and the 2D rotate, at the rotation's slot of upstream's order reversed, since it carries the angles and the depth together. `Perspective` is `Depth`, identity 0 (no perspective).
31. Where one scalar cannot carry a reveal's parameters, a companion shorthand does: `ClipCircle` is the radius fraction and `ClipCircleCenter` (a `RelativePoint`, default 50%, 50%) its center; `MaskSweep` is the progress and `MaskSweepAngle` (degrees) and `MaskSweepFeather` (default 0.2) its direction and soft edge. Each animates, reverts and rests on its own.
32. Recipes (Phase 25) are factories in the bridge, not shared static builders: each call returns a new `AnimationBuilder` that reads `Recipes.Tokens` (a public `MotionTokens` record with `Standard`, `Expressive` and `Reduced` presets) when called, so chaining on one touches no other caller's copy and replacing the tokens restyles later calls only. They live in the bridge because nearly every one names a shorthand. Stateful recipes are small bridge types instead: the `Tilt` attached property, and `Recipes.Typewriter`/`CountUp`, which take the `TextBlock` and return the playing `Animation`.
33. The recipe families are classes in `Monaco.Presto.AvaloniaBridge.Prebuilt` (`Entrances`, `Exits`, `Attention`, `Loops`, `Interactions`, `Loading`), with the `Recipes` facade, `MotionTokens`, `Edge` and the markup extensions in the root namespace. This deviates from the planned `Monaco.Presto.AvaloniaBridge.Recipes` namespace, which cannot sit beside a `Recipes` type in the root one (CS0101), and keeps one `using` enough for `Recipes.SlideIn(Edge.Left)` and `{presto:Fade}`.
34. Entrances state only start values (`.Opacity(from: 0)`), so they land on the element's own resting values; exits, attention, loops and interactions use to-values, since a `Motion` state rejects from-only values. Entrances and exits are transform and opacity only, and so run through `AnimateOnCompositor`, except `BlurIn`, `BlurOut`, `FlipIn` and `FlipOut`. `Connected.DefaultAnchorMotion` became from-only for the same reason. A recipe markup extension provides the exit form when set on `Presence.Exit` or with `Out=True` (a style `Setter` is not the property), and `Out=False` forces the entrance form.
35. Reduced motion is an app-set core flag, `PrestoDefaults.ReducedMotion`, opt-in per builder: `WhenReduced(Action<AnimationBuilder>)` stores an alternative that `ToParams()` builds on a fresh builder carrying this one's settings (including those chained after `WhenReduced`) but none of its properties or keyframes, so a stagger or callback survives while the reduced form states its own values. The flag is read when a builder becomes params; `MotionTracker` re-reads a state whose values were read under the other setting at its next transition. Every recipe supplies an alternative.
36. `PrestoDefaults.ReduceAll` covers animations without an alternative: the `Animation` constructor gives every tween a `Constants.MinValue` duration and no delay, keyframes and springs included, and forces one iteration, so each lands on its end values at once. Params built from a `WhenReduced` alternative, `Presto.Set` and plain timers are left alone; timeline children collapse like any animation. Presto never sets either flag on its own. To follow the OS setting, an app either writes `ReducedMotion` itself or opts in with `PrestoAvalonia.FollowSystemReducedMotion()` (Phase 49, decision 62), which writes the same flag from the bridge's platform probes.
37. Timelines and keyframes are not authored in XAML. Builders and recipes already reach XAML as values (`x:Static`, markup extensions, bindings, resources) wherever one animation is enough, and spelling out multi-step sequences as XAML elements adds verbosity without capability: such sequences usually need code-side targets and state that XAML resources cannot see. Decided after the post-Phase-33 gap review.
38. Child lists survive a callback unlinking a sibling mid-loop, a deviation from upstream, which shares the bug: `Presto.Remove` from an `OnUpdate` could unlink the child `Engine.Update` had cached as next, and the loop's second `RemoveChild` on the detached child then emptied the engine's list for good. `Helpers.RemoveChild` is a no-op for a child not linked into the parent, and the engine and both timeline child loops read their next child from an iteration cursor on `Clock` (`_nextChild`) that `RemoveChild` advances past a child it unlinks, so the rest of the list still ticks that frame. The loop shape is upstream's and nothing is deferred or allocated. Pinned by `EngineTests.RemovingATargetFromACallbackKeepsTheOtherChildrenTicking` and `TimelinesTests.RemovingTheNextChildsTargetFromAChildCallbackKeepsTheRestRendering` (FIXES-PLAN §1).
39. The Activity feed's one-off 39 px offset after dismissing the top row (FIXES-PLAN item 6) is closed as not reproduced: headless tests with the row selected before and after two live inserts, its Dismiss focused or not and `Animate.ItemLayout` on or off all keep the offset at `0, 0`, so neither `AutoScrollToSelectedItem`, focus hand-over nor the FLIP moves it. `ActivityFeedPageTests` keeps them as regressions.
40. A row counts as shown for `Presence.Reveal` only once a layout pass ends with it in the viewport, and a scroll anchor ends as soon as a pass finishes at an offset the change or its last correction did not leave (the reader scrolled), instead of correcting it away (Phase 39, [LIFECYCLE-PLAN](LIFECYCLE-PLAN.md) §10.7).
41. `Animate.ContentSize` and `PrestoAvalonia.AnimateContentSize` ease a host's real layout size on the UI thread instead of scaling it, holding the host's sole child at its natural size with an extra right/bottom `Margin` at `Animation` priority that eases to zero. The planned held `Width`/`Height` was dropped because it hides content that grows mid-flight; the margin lets every pass measure the content, so a change retargets from the size drawn. An axis eases only when the host grew by as much as its content did, within upstream's 1px, so a stretched axis moves at once. The margin is written in the `LayoutUpdated` that sees the change, so the next frame still shows the old size, and `ClipToBounds` is held only while a resize is in flight. Pinned by `ContentSizeTests` (`TheHostEasesToItsNewSizeAndLandsOnItExactly`, `TheFrameAfterTheContentChangesStillShowsTheOldSize`, `WrappingTextKeepsItsFinalLayoutAndIsClippedToTheHost`, `AChangeMidFlightRetargetsFromTheCurrentSize`) ([GAPS-PLAN](GAPS-PLAN.md) §3.2).
42. A `ContentSize` host owns its size. Swapping its `Content` or `Child` resizes from the size drawn now, while `Presence` ghosts the old content, clipped to the box the host had at the swap, and enters the new one. A layout transition on the same host eases only its position, whatever its mode, and layout moves beside a resizing host under the same parent land in one frame, since the resize already eases them. Pinned by `ContentSizePresenceTests` (`ASwapGhostsTheOldContentEntersTheNewAndResizesBetween`, `ASwapMidResizeRetargetsFromTheCurrentSizeAndClipsItsGhostThere`, `ALayoutTransitionOnAContentSizeHostEasesOnlyItsPosition`, `TheRowsBelowAnExpandingRowFollowItAndEndInTheirSlots`).
43. `LayoutAnimateMode.PositionAndSizeCorrected` counter-scales each direct visual child of a FLIP-scaled control with a render-thread `ExpressionAnimation` of `Vector3(1 / parent.Scale.X, 1 / parent.Scale.Y, 1)`, anchored by a static `CenterPoint` at the point as far across the child as the child sits across the parent's spare room, so it keeps its size and alignment. The child's `Scale` is taken through `CompositorRegistry` and restored to identity at completion, cancel or revert. Only direct children get an expression, and what the control draws itself, corner radius included, still scales; `Animate.ContentSize` is the answer for rounded surfaces. Watched on Win32 in a sample spike. Pinned by `CorrectedLayoutTransitionTests` (`TheChildKeepsItsAlignmentInsideTheCardAsItIsDrawn`, `TheChildIsBackAtIdentityWithNothingDrivingItOnceTheMoveLands`, `AGrowInterruptedMidFlightKeepsTheCorrection`, `ACorrectedGrowTakesTheScaleOverFromACompositorAnimationOnTheChild`) and `ReferencePagesTests.TheCorrectedAvatarKeepsItsSizeWhileItsCardGrows`.
44. `ScrollObserverParams.Pin` holds the target with its own `"X"`/`"Y"` transform shorthand, `Clamp(Scroll − OffsetStart, 0, Distance)`, written through `RenderTransformComposer.Set` inside the scroller's `Offset` change notification rather than on the next scroll tick, so it never trails the content by a frame. The pin owns those shorthands, so a linked animation should drive the target's descendants; it is lifted while the bounds are measured, since `TranslatePoint` includes the render transform. Sheets (Phase 63c) are a control, `Sheet` with a sealed `Drawer` subclass, not an attached form: a sheet needs a scrim over its whole host and an edge strip to swipe from while closed, siblings an attached property on the panel could only add by reaching into its parent's children, which belong to the parent. The control is not templated, since the bridge ships no themes; it builds its scrim, panel and strip as visual children and takes its look from its `Content`. Its drag is its own rather than a `Draggable`, whose press captures the pointer and so could never hand a touch scroll to an inner `ScrollViewer`. Pinned by `SheetTests` and `DrawerTests`.
105. The carousel (Phase 64a) is a control, `Pager`, not an attached form on Avalonia's `Carousel`. Avalonia 12's `Carousel` pages through a `VirtualizingCarouselPanel` with its own swipe (`IsSwipeEnabled`) and page transition, realizes only the slides it shows, and exposes no continuous offset. A Presto drag with inertia, a parallax value per slide and a looping strip would replace its panel, its swipe and its transition, which is the whole control. Like `Sheet` (decision 104) it is not templated: its slides sit on a private strip panel that lays them out in columns of the pager's width, and a `Draggable` moves the strip through its X shorthand. A looping pager arranges the strip again on every move, placing each slide at the copy of its column nearest the page shown, rather than cloning slides. The name avoids a clash with `Avalonia.Controls.Carousel`. Pinned by `PagerTests`.
106. The toast host (Phase 64b) is `ToastHost`, an `ItemsControl` that owns its `Items` and is filled only through `Show`, not a host over a view model's collection: a cap trimmed from inside the collection's own `CollectionChanged` cannot change it there, so `Show` trims before it adds. It keeps Fluent's `ItemsControl` theme (`StyleKeyOverride`), and its motion is the item template's `Presence` and the host's `Animate.ItemLayout`, so it adds no animation properties of its own. A swipe is 63b's `Swipe` on the item container, with no actions, and a swiped toast is removed at opacity 0, which `Presence` reads as an unload, because it has already slid out. Pinned by `ToastHostTests`.
107. `Presto.GetAnimations` keeps omitting paused animations, for parity: anime.js 4.5.0's engine drops a paused tickable from its children on its next tick (`engine.js`) and keeps no other list, so a paused animation is reachable only through the handle its caller holds. Listing it would need a per-target registry kept by every pause, resume, completion and cancel. Code that pauses an animation already holds it, as `Toast` holds its countdown, which removed MicroInteractions' `Tag` workaround. Pinned by `UtilsTargetsTests.GetAnimationsDropsAPausedAnimationOnceTheEngineReleasesIt`.
108. The modal host (Phase 64c) is a control, `Modal`, with `Open(element)`/`Open(point)`/`Close()` methods over a two-way `IsOpen`, not a static `Modal.Open(content, from:)` that would build an overlay in the window's `OverlayLayer`, nor an attached `IsOpen` on an overlay control. Every page that hosts one places it over a particular view, under the page's own chrome (Storefront's catalog, the Card gallery's field, Connected's stage), and a static builder would have to find that view's bounds and draw above everything. As with `Sheet` (decision 104) the scrim is a sibling of the content, which an attached property could add only by reaching into a parent's children. The origin is an argument to `Open` rather than a property, since it belongs to one opening. Its open and close motion are fixed by `Recipes.Tokens` rather than exposed as builders, since all three pages wanted the same circle or none. Pinned by `ModalTests`.
109. The accordion (Phase 64d) is an attached form, `Accordion.Enabled` on an `Expander` or a `TreeViewItem` with `Accordion.Group` for single-open and `Accordion.Chevron` on a template element, not a style or a templated control: the bridge ships no themes (decision 104), and the gallery nav keeps its own `TreeViewItem` template. The eased body is `Animate.ContentSize` on the item itself, whose template root never hides, rather than on a wrapper around the body, so no template needs a part for it; the body (`ExpanderContent` or `PART_ItemsPresenter`, the parts Fluent hides) fades out under `Presence`'s held hide before it folds and replays its entrances through `EnterOnShow`. A chevron finds its item through its templated-parent chain, so Fluent's chevron, two templates deep, works; that chevron's path is given a `TransformOperations` render transform, which Avalonia's `TransformAnimator` skips, so Fluent's own 62 ms flip of its `RotateTransform` does not add to the spring on its border. Pinned by `AccordionTests` and `NavMotionTests`.
110. `GridLength` has a pixel-only codec (Phase 64e, the candidate from Phase 52): a pixel length decodes to its pixel count, so a number, a relative number or a pixel length animates `ColumnDefinition.Width`/`RowDefinition.Height` in one `Animate` call, and a frame below 0 (a spring's overshoot) writes 0. A star or auto length at either end throws `ArgumentException`, as a discrete value given what it cannot be does (decision 73), rather than switching as a discrete value: a column that jumped between `*` and pixels mid-tween would reflow its whole grid. `Pane.Collapse`/`Expand`/`Toggle` build on it for a `Grid` column, lifting `MinWidth` for the run, clipping the content below it through a negative right margin, and ending on a local width with the animation reverted, since a held animation value would mask a `GridSplitter`'s writes. Pinned by `CodecTests`, `CollapsiblePaneTests` and `NavPaneTests`.
111. `Follow.Draw` (Phase 65b) follows one number, the share of a shape's stroke drawn from its start, written as the `"Draw"` property's `"0 p"` and clamped to 0–1, rather than a start/end pair: every `Follow` shorthand is one `double` eased by one `Follower` or written from one `MotionValue`, and every value-bound draw in the sample (Gestures' pull ring, Carousel's autoplay ring) starts at 0. A slice that starts elsewhere, such as Dashboard's donut, stays a `"Draw"` tween. Unlike the transform and blur shorthands it has no base under an animation: it writes the shape's dashes through `DrawAccessor` as a `"Draw"` tween does, so the later write wins, and releasing it restores the dashes the shape had. `ProgressRing` builds on the same rule: it draws `Value` as it is and takes its easing from `{presto:Follow}` or `Follow.Bind`, which already snap under reduced motion and draw a `MotionValue` unsmoothed, instead of easing every change itself and lagging a value driven each frame. Pinned by `FollowTests` and `ProgressRingTests`.
112. The submit-button recipe (Phase 65b) is an attached form, `SubmitButton.State` on any `Button` with `SubmitButton.Run(button, work)` setting it around an awaitable, not a templated control or a builder chain: a view model binds the state, a handler awaits `Run`, and the button keeps its own template and content. The spinner and mark live in a layer appended to the button's `VisualChildren`/`LogicalChildren` (decision 103's accessors) and arranged at its bounds as they change, so no content needs a part. The outcome is a check or a cross drawn in with `Recipes.DrawIn` after the spinner fades, not a `MorphTo` of the spinner's arc: the arc stops at whatever angle the wait left it, and a cross is two strokes. Collapsing and expanding animate `Width`, `CornerRadius` and, with `SuccessBrush`/`FailureBrush`, `Background`, and the expand reverts its animation when it lands, so the button ends on its own local or styled values. Pinned by `SubmitButtonTests`.
113. A scroll reveal outside a virtualizing list (Phase 65a) is `Presence.Reveal`, not a new `Scroll.Reveal`: one idea keeps one name, and the element picks its trigger by where it sits. Under a `ScrollViewer` with no `VirtualizingPanel` between them, the element gets a private `ScrollObserver` on its scroller (`RevealThreshold` is its `Enter`) and is held at opacity 0 at `BindingPriority.Animation` from its attach until it crosses, since a threshold inside the viewport would otherwise show it before its entrance starts from its own from-values. Crossings are collected and played on the next engine tick as one batch per window in reading order (top, then left), not attach order, so a stagger runs down the page. With `RevealOnce` the observer is reverted after the reveal; without it, leaving the view reverts the reveal and holds the element hidden again. Rows of a virtualizing list keep the realization path (decision 40). Pinned by `ScrollRevealTests`.
114. Pull to refresh (Phase 65c) is a control, `PullToRefresh`, not a restyled Avalonia `RefreshContainer`: that container's pull comes from a `PullGestureRecognizer` that takes touch and pen only, and its `RefreshVisualizer` turns a fixed icon through its own composition animation, so neither the mouse pull, the rubber band nor the arrow and ring could be Presto's without replacing both. Like `Sheet` (decision 104) it handles the pointer itself rather than through a `Draggable`: the damping `r(1 − e^(−d / r))` is applied to the pointer's travel, never to the drawn value, so the release springs from where the content is drawn and lands exactly on the threshold. That sidesteps SAMPLES-PLAN §8 row 30, where a `Draggable` axis modifier is re-applied to its own output on release; the modifier stays documented as having to be idempotent, and the Gestures page's `_pulling` gate is gone with its `Draggable`. The work is a `Func<Task> Refresh` the control awaits, holding the content at the threshold until it ends, rather than an `ICommand`, which cannot be awaited. Pinned by `PullToRefreshTests`.
115. The bloom page transition (Phase 65d) is a recipe, `Recipes.PageBloom()` returning a `PrestoPageTransition` (`Enter` a `ClipCircle` reveal, `Exit` finishing any part-revealed circle, `Stacking = IncomingAbove`), not a transition type of its own, so it inherits the take-over and revert rules every page recipe has. A transition is handed only the two hosts, so the origin comes from input the bridge watches: one tunneling `PointerPressed` class handler on `TopLevel` records the last press per window, a `KeyDown` clears it, and the bloom that uses it spends it, so a keyboard or programmatic navigation blooms from the host's center. The new page's tiles are the children of its first `Panel`, the one shape the transition can find without a marker property; they rise in at 65 %. Pinned by `PageBloomTests`.
116. The flip card (Phase 65e) is a control, `Flip`, with `Front`/`Back` content and `IsFlipped`, not attached properties on a page's own panel: the card that turns and the mirror on the back face are its own children, so neither a page's layout nor its `RenderTransform` is touched, and a face never sees the rotation it sits in. It is not templated (decision 104). Pinned by `FlipTests`.
117. Color tweens interpolate RGB with premultiplied alpha (Phase 68), a deliberate deviation from anime.js 4.5.0, which blends straight alpha: a fade from transparent took on the transparent color's RGB (a transparent teal flashed green on its way to gray), the same footgun Avalonia's own brush transitions have, and CSS Color 4 interpolates this way. A solid color is `c = sqrt(lerp(a₀·c₀², a₁·c₁², p) / lerp(a₀, a₁, p))` with alpha linear; `BrushCodec.ColorAt` resamples gradient stops the same way in plain gamma. Equal alphas keep the old expression bit for bit, so the ported `colors` tests and fixtures are unchanged, and ends are exact. Blend composition sums straight per-channel deltas and stays straight; color slots in gradients and box shadows lerp as plain complex numbers (COLOR-SPACES-PLAN §6 defers them). Pinned by `PremultipliedColorTests` and `CodecTests`.
118. Color interpolation spaces (Phase 30) are a utility, not a per-tween setting: `PrestoColor.Mix(from, to, t, space, hue)` does CSS Color 4 mixing in `Srgb`, `LinearSrgb`, `Oklab` and `Oklch` (premultiplied alpha, powerless hue below chroma 4e-4, CSS gamut mapping, exact ends), and `TweenKeyframesBuilder.Color(from, to, space, hue, …)` expands one color tween into keyframes on that path whose eases are slices of the tween's ease, so timing is exact and only the color between segment ends is the existing pseudo-linear blend; segments are fitted until that blend is within deltaEOK 0.02 of the path, at most 16. The capability is the OKLCH hue path, not the space, and keyframes express it without per-tween buffers, retarget rules or codec color slots. One deliberate deviation from CSS: equal chromatic hues under `Increasing`/`Decreasing` make a full turn instead of none, so a hue cycle is `Color(c, c, Oklch, Increasing)`. Existing tweens are unchanged. Deviations and the measured path tolerance are in COLOR-SPACES-PLAN §7. Pinned by `ColorConversionTests` and `ColorKeyframesTests`.
Open (confirm before the relevant phase):

- `Timeline.Set` takes only a `TimelinePosition`, so a stagger cannot position a setter group as it can upstream; add the overload if a sample needs it.
- Function-based `composition` (upstream runs `composition` through `getFunctionValue`): `TweenParams.Composition`/`AnimationParams.Composition` are plain enums, so a per-target delegate is not expressible. No ported test needs it; decide whether parity is worth making the property function-capable.
- `autoplay: onScroll(...)`: `TimerParams.Autoplay` is a `bool?`, so a scroll observer is attached with `observer.Link(timer)` after creating the timer with `Autoplay = false` instead. Widening the parameter to accept an observer is an API-pass decision; reverting the linked timer already reverts the observer, as upstream does.
- Rotation unit for the bare `Rotate` shorthand: degrees (Avalonia `RotateTransform.Angle`) is the natural default; upstream defaults to `deg` too, so parity holds. Confirm we do not want radians anywhere by default.
- Lazily resolved timeline-child targets: a child's targets are fixed when it is added, so a timeline over a `SplitText`'s pieces can neither be built before the split has measured nor survive a re-split (SAMPLES-PLAN §8 row 4). The workaround is documented on `TextSplitter.AddEffect`; decide whether a child should resolve its targets at first render, or `Timeline` should re-point one.
- Per-target `TextModifier`/`Modifier`: both take the number alone, with no `(target, index, total)`, so counters that want their own precision need an animation each (SAMPLES-PLAN §8 row 17). Upstream's `modifier` has the same shape, so parity holds; decide whether to resolve them per target like every other function-based value.
- Relative or delta `To` for blended tweens: a blended tween's `To` becomes the additive group's base, so a layered effect has to aim at the destination of the animation beneath it, and aimed around zero drags it back (SAMPLES-PLAN §8 row 22). Decide on a spelling for "add this much" that does not move the group's base.
- One playback model per `CompositorAnimation`: each target gets its own paused mirror `Animation`, ticked on the UI thread, plus its own composition animations, so 5 000 visuals run at 51 UI / 51 render fps against 88 / 129 for UI-thread animations (SAMPLES-PLAN §8 row 28). The mirrors differ only by resolved delay and values; decide whether sharing one model across targets is worth the rework of per-mirror completion.
- `AnimateOnCompositor` ignores `RenderTransformOrigin`: `CompositorAnimation` drives `CenterPoint` with a fixed `Size * 0.5` expression, so a ball with a bottom origin squashes about its center on the render thread (SAMPLES-PLAN §8 row 32). Build the expression from the control's `RenderTransformOrigin`, as Avalonia does for `RenderTransform`.
- `Presence` inside a `TreeView` resolves a nested item to the outer list (Phase 52). A section's items panel has the section `TreeViewItem` as its templated parent, and that is an item container of the `TreeView`, so `OwnerOfItem` answers the `TreeView` for a page. The `TreeView`'s `ItemChanges` never see the section's own collection change, so a page removed from its section is classified `Recycle` and plays no `Presence.Exit` (a page added would read as `Realize`). The gallery nav therefore ghosts only whole sections out; filtered-out pages vanish while `Animate.ItemLayout` closes the gap. Decide whether `OwnerOfItem` should stop at the nearest `ItemsControl` whose own items panel hosts the container (the section), so nested lists decide for their own items.
- A layout transition trails a content size resize beside one of its ancestors (Phase 52). `ContentSizeTransition.ResizingBeside` lands a control's move in one frame only when the control itself sits beside the resizing host; `LayoutTransition` measures in window space, so a page reflowing inside the next section of the gallery nav sees its section pushed a few pixels each frame and flies after it while the section header has already landed. The nav therefore arms page reflow only while a search filters and the section's `Accordion.Enabled` (its `Animate.ContentSize`) only otherwise. Decide whether `ResizingBeside` should also hold when any ancestor up to the host's parent is beside the host.
- No `Follow.RotateY` shorthand (Phase 53d). `Follow` covers the 2D transform shorthands, `Blur` and, since Phase 65b, `Draw` (decision 111), so the Swipe deck card's lean subscribes to its mapped `MotionValue`'s `Changed` and writes `RotateY` with `PrestoAvalonia.Set`, unsubscribing by hand when the card leaves (`SwipeDeckPage.Bind`). `RotateX`/`RotateY` shorthands would make it one `Follow.Set*` call, but a lean reads as 3D only with `Perspective` beside it, which the composer keeps per visual rather than per shorthand; a candidate, not built.
- Timeline forward jump from 0 renders a later-added `.Set` out of order (Phase 53e, possible core bug). In Title sequence, `.Set(Cards.Children, b => b.Opacity(0), 0)` is added after the cards' fade-up. A jump that starts at time 0 and lands past both (`Complete()`, `Seek(Duration)`, `KeepTime`'s re-seek) renders the `Set` last, so the cards end hidden. The page works around it under reduced motion (`TitleSequencePage.LandSequence` seeks through the `cards` label, then to `IterationDuration`). Reproduce in a core test against anime.js 4.5.0 `seek` behavior before deciding whether it is a parity bug or upstream semantics.
## 8. Prebuilts (later)

Ready-made effects on top of the engine: named, parameterized recipes and the few bridge pieces they need, so common UI
motion is one call or one XAML attribute rather than a hand-assembled animation. Effect shorthands, masks and reveals,
2.5D tilt and flip, and the entrance, exit, attention, loading, counter and reduced-motion recipes were built in
Phases 24–25 ([MOTION-KIT-PLAN.md](MOTION-KIT-PLAN.md)); shader and pixel transitions were not. Each should land
as an `AnimationBuilder` (or a small bridge type where state is involved), usable from code, `Animate.OnAttached`,
`Presence.Exit` and the compositor where the properties allow.

- **Effect shorthands.** *Built in Phase 24* (decisions 29–30): `Blur` and `ShadowX`/`ShadowY`/`ShadowBlur`/`ShadowColor`/`ShadowOpacity` over a bridge-owned `Visual.Effect`.
- **Shader and pixel transitions.** *Planned as Phases 28–29* ([IMAGE-EFFECTS-PLAN.md](IMAGE-EFFECTS-PLAN.md)): color filters and dissolve, pixelate, ripple and wipe transitions on a `FilteredImage`, through Skia's built-in filters rather than shaders.
- **Masks and reveals.** *Built in Phase 24* (decisions 29 and 31) as the `ClipInset`, `ClipCircle` and `MaskSweep` shorthands; the text mask and `MorphTo` clip geometry were not.
- **Attention recipes.** *Built in Phase 25* (decision 32): `Shake`, `Pulse`, `Wobble`, `Jelly`, `Heartbeat`, `Tada` and `Bounce`, keyframed builders with an `intensity` factor.
- **Entrance and exit recipes.** *Built in Phase 25* (decisions 32–34): fade, slide, scale, pop, blur and flip pairs for `Presence.Enter`/`Initial` and `Presence.Exit`, with `stagger: true` for a list, and the `{presto:Fade}`-style markup extensions that pick the exit form under `Presence.Exit`.
- **Loading recipes.** *Built in Phase 25*: `Shimmer` (a `MaskSweep` loop rather than a Phase 19 gradient), `Spinner`, `Dots` and `Indeterminate`.
- **Tilt and 2.5D.** *Built in Phase 25*: the `Tilt` attached property follows the pointer with real `RotateX`/`RotateY` and `Perspective` (Phase 24) on the UI thread, not a compositor skew-and-scale approximation, and `FlipIn`/`FlipOut` flip a card.
- **Counters and text.** *Built in Phase 25*: `Recipes.CountUp` (formatted through `TextModifier`) and `Recipes.Typewriter` over `SplitText`. Per-line, per-word and per-character reveals came in Phase 38 (`TextReveal.Pieces` and the `LineRise`…`CharCascade` recipes, [PREBUILTS-2-PLAN](PREBUILTS-2-PLAN.md) §3). `Recipes.RollDigits`, an odometer roll of the changed digits, came in Phase 49 (decision 63).
- **Reduced motion.** *Built in Phase 25* (decisions 35–36): `PrestoDefaults.ReducedMotion` picks each builder's `WhenReduced` alternative and every recipe has one; `ReduceAll` turns the other animations into instant sets. Following the OS "reduce motion" setting is opt-in through `PrestoAvalonia.FollowSystemReducedMotion()` since Phase 49 (decision 62), or the app sets the flag itself.
